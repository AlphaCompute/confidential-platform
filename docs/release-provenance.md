# Release candidate provenance and publication

The release workflow now requires reusable CI, including non-skippable KMS/PostgreSQL regressions, before building. Each image is built on two separate runners with no shared build cache. It compares image configuration IDs, ordered layer digests, source commit and material hashes. Candidate archives retain the lockfile, dependency inventory, image inspection and builder version and receive GitHub build-provenance attestations. Actions are pinned by verified commit. Production KMS and dev-root images remain distinct; dev-root must never enter a production platform document.

There is no automatic registry push in this workflow. A candidate is not customer approval and is not an accepted Rafay offering. A separately administered publisher must verify the expected repository/workflow identity in the attestation, source commit, candidate archive hash, independent build comparison, complete OS/native/Rust/Python SBOM, dependency approval and security regression evidence. After import, verify the resulting registry manifest digest and generate compose bytes from that digest. Customer approval and custodian operations happen outside CI/Rafay.

The dependency inventory is not a complete SBOM. Docker build-stage Alpine packages and Python transitive dependencies still need immutable, hashed resolution; an independent candidate build may expose their drift. The workflow has been authored locally but has not run in GitHub for this change. No independently reproduced image, live provenance attestation or release digest is claimed here.

For an offering, native catalogue installation/read-back, versioned price binding, tenant isolation, real invoices and its application/provider acceptance evidence are additional requirements. The surrounding integration workspace's `review-checks/publication_gate.py` verifies the externally signed acceptance envelope and returns the only publishable offering names. Its public pin must be administered independently of the envelope. All offerings currently remain blocked.
